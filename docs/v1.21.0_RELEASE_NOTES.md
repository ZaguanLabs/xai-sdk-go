# xAI Go SDK v1.21.0

Ports the changes in official Python SDK 1.21.0: opaque safety identifiers and policy guidelines for nsfw, violence, and profanity, with the decline behavior. Native guideline values validate dictionary inputs, and protobuf guidelines retain the upstream pass-through path. Model compatibility and repeated categories remain server validations.

Source: official PyPI xai_sdk-1.21.0.tar.gz, SHA-256 `1c85e8c2c55b64da95bf9e5b0620ce683062c13a971e508b72ebf1025750d1d1`. Built with `python -m build` and unpacked the built source archive under ignored `docs/xai-sdk-python/`.

The protocol audit also corrects older gaps: file metadata field numbers and upload oneofs, native streaming Files RPCs, file expiry and download formats, service tiers, generated output files, inline file bytes/URLs, context compaction, code-execution file includes, attachment-search limits, byte-based chunking and batch-status filters. Streaming response assembly retains output-file and service-tier metadata.

Compatibility: generated protobuf content/citation fields now use the official oneofs. Direct protobuf struct users must use the generated `Source`/`Citation` wrapper types and getters; high-level image, video and chat helpers keep their existing signatures. `File.TeamID` remains as an empty legacy field because the official metadata no longer contains it. `FilesOrdering` retains its Go name to avoid a collision with the RAG ordering enum, with aliases for the older Go constants. The main client uses native gRPC for Files; the REST constructor remains available for existing custom gateways.

Validation: all official public API descriptor fields, enum values, optional presence and RPC signatures match (including the documented Go enum rename). Race tests, vet and build pass with Go 1.26.10; the pinned linter reports zero issues and govulncheck reports zero affected vulnerabilities. Tests cover native binary uploads across multiple chunks, streaming downloads, pagination, compaction failure atomicity, inline-file ownership, guideline validation, independent protobuf copies, optional empty identifiers and exact wire numbers. Python protobuf 7 runtime support has no Go runtime equivalent; the Go runtime uses native generated protobufs.

Security/toolchain: update gRPC to 1.83.1 and `golang.org/x/net` to 0.60.0 with compatible transitive dependencies. These fix the issues reported by the required vulnerability scan, including [the gRPC HTTP/2 fragmentation advisory](https://pkg.go.dev/vuln/GO-2026-6348). The [patched network module](https://github.com/golang/net/blob/v0.60.0/go.mod) requires Go 1.26.0; the module and CI now use Go 1.26 with the 1.26.10 toolchain. Applications on Go 1.25 must upgrade before using this release. The 1.26.10 toolchain also addresses the standard-library advisories found during the release scan, including the [certificate verification advisory](https://pkg.go.dev/vuln/GO-2026-6809).
